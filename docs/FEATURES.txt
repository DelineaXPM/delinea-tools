delinea-tools - FEATURES
========================

This repository ships the delinea-util command. Its authentication, transport,
secret-resolution, and CI-formatting implementation comes from the sole module
dependency, github.com/DelineaXPM/delinea-common.


TARGETS AND AUTHENTICATION
--------------------------

  - Secret Server and Secret Server Cloud password grants, with optional AD
    domain.
  - Delinea Platform client-credentials grants.
  - A pre-obtained bearer token can skip the grant.
  - Interactive Platform login supports native-account MFA challenges.
    Federated/SSO redirects are refused.
  - The target can be explicit (--target ss|platform) or inferred from the
    configured credential pair. check can probe an unset target without sending
    a Delinea credential.
  - Passwords, client secrets, bearer tokens, and interactive answers are never
    accepted as command-line values. Use environment variables or
    --secret-stdin.


RAW REST
--------

  - "delinea-util METHOD PATH" performs one authenticated request and streams
    its response body to stdout.
  - GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS, token, and check are supported.
  - -d accepts a literal body, @FILE, or @- for stdin. -H accepts ordinary
    headers or @FILE; gateway headers are file-only.
  - -i includes response status and headers. -v writes a credential-redacted
    request/response summary to stderr.
  - --vault routes through Platform vault discovery; --vault-id selects a
    specific broker entry. Alternate vault ports require an explicit
    host:port allowlist entry.
  - Safe reads may retry transient transport/status failures. Writes are never
    retried or redirected.


SECRET DELIVERY
---------------

  - "secrets run" injects resolved values into one child. On Unix it normally
    exec-replaces itself; on Windows, and when a Unix stdin payload must be
    streamed, it supervises the child and propagates its exit code.
  - "secrets print" writes a selected format to stdout or an explicit --out
    destination.
  - "secrets template" renders a Go text/template after all mappings resolve.
  - Mappings use NAME=field#id or NAME=field@\folder\path. PREFIX_*=#id expands
    non-file fields with usable slugs.
  - File fields are downloaded and substituted transparently, subject to count
    and total-byte limits.
  - Delivery validates and resolves the entire mapping set before publishing
    anything and refuses variable collisions. Mapping or format failures emit
    no partial payload; sink I/O failures can still be partial on non-atomic
    stdout, append-file, and special-file protocols.
  - Modes include env, stdin, sh, json, raw, github-env, github-output, and ado.
  - GitHub and Azure modes validate platform-reserved names and register masks
    before publishing a value. Azure secret variables are single-line only.


DIAGNOSTICS
-----------

  - check reports configuration, reachability, credential validity, and every
    requested mapping without printing a secret value.
  - --no-auth performs configuration and reachability checks without a grant.
  - --json and --quiet provide automation-friendly output.
  - --readme, --tree, --version, and command-specific help are embedded in the
    binary.


OUTPUT AND EXIT CODES
---------------------

  - Secret-bearing stdout refuses a terminal unless explicitly armed.
  - Regular --out files are atomically replaced at mode 0600 on Unix; symlinks
    are refused. Explicit special sinks and runner-owned append files retain
    their existing mode.
  - Raw calls and secret-delivery setup use:

        0  success
        1  usage or configuration error
        2  authentication or vault discovery failure
        3  transport, TLS, DNS, or timeout failure
        4  completed non-2xx HTTP response

  - After launch, secrets run returns the child exit code. check returns 0 for
    a clean report and 1 for any finding.


SECURITY PROPERTIES
-------------------

  - Authentication credentials never appear on argv.
  - Configured credentials and sensitive headers are redacted from errors,
    formatted configuration, and operational logging.
  - A secrets run child receives a declared environment; unrelated ambient
    variables are not inherited.
  - TLS trust changes are scoped to this client. Grants and writes never follow
    redirects, and cross-origin API redirects are refused.
  - Platform vault-broker URLs are untrusted input and are validated before use.
  - No token or credential is persisted. Disk output occurs only when requested.


CI/CD
-----

  - Scoped injection with secrets run is preferred when the consumer can be
    wrapped.
  - GitHub Actions environment and step-output command files use validated
    names, collision-safe delimiters, and mask-before-write ordering.
  - Azure Pipelines logging commands escape protocol metacharacters and mark
    variables secret before publication. They are available to later steps in
    the same job and require explicit environment mapping for scripts.
  - Shell export output supports same-step GitLab and local shell use without
    artifact transport.
  - docs/CI.txt contains complete recipes and platform caveats.


PORTABILITY AND DEPENDENCIES
----------------------------

  - Linux, macOS, and Windows are built and tested.
  - The command has exactly one direct Go module dependency:
    github.com/DelineaXPM/delinea-common v1.0.0. That module uses only the Go
    standard library.
  - An offline supply-chain test rejects any additional, indirect, replacement,
    exclusion, or retraction directive.


TESTING
-------

  - The default suite is offline and deterministic.
  - CI runs race tests on Linux, macOS, and Windows, coverage enforcement, vet,
    cross-builds, dependency checks, and vulnerability scanning.
  - Scheduled quality runs repeat the shuffled suite and fuzz every CLI target.
  - Live E2E tests execute the built command against both supported product
    paths. Strict mode fails when any documented fixture is absent.
