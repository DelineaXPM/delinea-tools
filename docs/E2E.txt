delinea-util end-to-end tests
============================

The default suite is offline and deterministic. Live tests build and invoke the
real command only with the e2e tag:

  go test -count=1 -tags e2e ./...

Each live test normally skips when a required fixture is absent. Set
DELINEA_TOOLS_TEST_REQUIRE_E2E=1, or run make e2e-strict, to turn every missing
fixture into a failure. The scheduled workflow uses strict mode.

The scheduled/manual workflow runs the live suite serially on Ubuntu, macOS,
and Windows. Its credentials are environment secrets in the live-tests
environment, which accepts only main. A manual run against another branch
therefore cannot receive live credentials. Overlapping live workflows are
queued, and the OS matrix permits only one runner at a time, so shared tenant
fixtures are not exercised concurrently by this repository.

Use throwaway test objects. Tests never print configured secret values, but the
write cases create and delete folders or secrets beneath the configured folder.
A cleanup is registered before each delete attempt.

The two CLI suites cover:

  - cmd/delinea-util/e2e_test.go: raw calls, documented exit codes, token reuse,
    credential stdin, Platform vault routing and broker listing, check output,
    and Secret Server/Platform create-delete cycles;
  - cmd/delinea-util/secretscmd/e2e_test.go: resolution by ID and path, raw and
    template output, atomic/no-clobber file output, mode 0600 on Unix, and child
    environment injection.


SECRET SERVER FIXTURES
----------------------

  DELINEA_TOOLS_TEST_SS_URL          base URL of a Secret Server or SSC tenant
  DELINEA_TOOLS_TEST_SS_USERNAME     local user with API access
  DELINEA_TOOLS_TEST_SS_PASSWORD     its password
  DELINEA_TOOLS_TEST_SS_SECRET_ID    numeric ID of a readable secret
  DELINEA_TOOLS_TEST_SS_SECRET_PATH  path of that same secret, backslash
                                     delimited with a leading backslash
  DELINEA_TOOLS_TEST_SS_SECRET_FIELD readable field slug on that secret
  DELINEA_TOOLS_TEST_SS_SECRET_VALUE expected field value
  DELINEA_TOOLS_TEST_SS_FOLDER_ID    folder in which the user can create secrets
  DELINEA_TOOLS_TEST_SS_TEMPLATE_ID  template used for the write cycle
  DELINEA_TOOLS_TEST_SS_SITE_ID      site used for the write cycle (usually 1)

The path fixture must name the same secret and field value as the ID fixture.
The configured template must have at least one required non-file field. The
suite fills every such field with a generated value before creating the secret.


PLATFORM FIXTURES
-----------------

  DELINEA_TOOLS_TEST_PLATFORM_URL            Platform tenant URL
  DELINEA_TOOLS_TEST_PLATFORM_CLIENT_ID      service-identity client ID
  DELINEA_TOOLS_TEST_PLATFORM_CLIENT_SECRET  service-identity client secret
  DELINEA_TOOLS_TEST_PLATFORM_SECRET_ID      readable vault secret ID
  DELINEA_TOOLS_TEST_PLATFORM_SECRET_PATH    path of that same vault secret
  DELINEA_TOOLS_TEST_PLATFORM_SECRET_FIELD   readable field slug
  DELINEA_TOOLS_TEST_PLATFORM_SECRET_VALUE   expected field value
  DELINEA_TOOLS_TEST_PLATFORM_FOLDER_ID      vault folder owned by the identity
  DELINEA_TOOLS_TEST_PLATFORM_TEMPLATE_ID    vault template for the write cycle
  DELINEA_TOOLS_TEST_PLATFORM_SITE_ID        vault site for the write cycle

The Platform identity must be able to discover the active default vault and
create/delete folders and secrets beneath the configured folder.


NOT COVERED
-----------

Interactive login is not automated because its out-of-band challenge requires
a human. Its state machine is covered by delinea-common's offline tests against
a fake Identity API.
